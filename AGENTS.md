# For AI agents working on DayMax

You are the workforce (product, engineering, security, docs). The user is the product owner. He is a consumer, not a developer — explain in plain language, tell him exactly which buttons to click, and **ask before expanding scope**.

## Ground rules

1. **Never commit private data.** The owner's real spreadsheet (`main_max_inches*.xlsx`) and any real diary exports stay out of git. `.gitignore` enforces this — do not weaken it. Sanitized fixtures live in `fixtures/`.
2. **Never put secrets in code.** Supabase keys live in `.env.local` (local) and Vercel env vars (deployed).
3. **Privacy is the product.** 15-minute labels are a diary. Any future Compare/friends feature shares category totals only, unless a user explicitly sets `raw_labels` per track. Default-deny.
4. **The day grid must beat Excel.** Fill-range, keyboard, copy-yesterday are core features, not extras. Any change that makes logging slower is a regression.
5. **Import never guesses.** Unparseable cells become warnings shown to the human, not silently coerced data.
6. **Minors** (Phase 3): under-18 accounts default to totals-only sharing; body-measurement tracks are opt-in with guardian acknowledgment.

- XLSX ROUND TRIP: `looksLikeGrid()` in xlsxIO MUST delegate to `findTimeColumn()` in gridParse. It used to be a second hand-rolled time-column test that accepted the STRING "00:00" but required the NEXT cell to be a Date or number — and `slotToTime()` emits strings, so every workbook DayMax exported was silently skipped by DayMax's own importer ("Skipped sheets: ...", 0 slots). Never reimplement the grid test; `src/lib/__tests__/roundtrip.test.ts` pins strings, Excel serials and Date cells. Anything generating a grid externally should write real time cells, which parse on every version.
- COMPARE-TO-YOURSELF (`src/app/recap.tsx`, on Home): everything competitive measures you against other people; these two do not. Week-vs-your-own-normal (needs >=14 prior days before it will speak) and On-this-day at 1/3/6/12 months, which surfaces the LABELS you wrote — that is the memory, not the hours. `monthsBack()` clamps the day-of-month, so 31 Mar minus a month is 28 Feb and not 3 Mar.
- CHARTS EARN THEIR PLACE: Arena shipped with five ranked tables and ZERO charts (`src/app/arena/charts.tsx` fixes that: race / spread / day shape / head-to-head). Analytics (`/overview`) had eleven charts but `trends` and `correlations` defaulted to FALSE, so the page most people saw had three — and it only ever described Life. `overview/pursuit-summary.tsx` now answers "how am I doing at everything" first, one card per pursuit. House rule: every chart leads with a sentence of plain English computed from the actual numbers ("Tony leads on 300h, you are 180h back"), never a bare axis. Profile leads with the year strip under Pursuits; the second month grid and the year heatmap were deleted as duplicates of it.
- DEMO TEXTURE (`scripts/gen_demo_seed.py`): the cast used to paint 7-12 clean blocks a day, so every day was a 58-81% copy of the previous one and they mirrored EACH OTHER 57-67% — six timetables with the names swapped. `texturise()` breaks long runs with plausible short interruptions, with a DIFFERENT fragmentation signature per character (Tony 23 blocks/day, Thor 12), and `resolve()` fixes the old blank-day bug where unpainted slots defaulted to '0' = Sleep, which turned every gap in a script into a phantom nap and inflated sleep to 9-11h. Blank days now start from a GAP sentinel; leading/trailing gaps become night, interior gaps extend the previous block, and BEDTIME stops an evening that runs out at 20:00 reading as sleep from 20:00. To update demo days run `supabase/seed/refresh_demo_days.sql`, NOT demo_marvel.sql — the latter deletes auth.users then writes profiles.is_demo, which 0030's trigger now rejects, so it fails after deleting the cast.
- MISSING TIME (`src/lib/gaps.ts`, `/gaps`): a day is 96 slots, so a 90/96 day is 22.5h and a year of those averages ~23.1h/day, not 24. That is correct arithmetic and a useless answer, so the app names the days instead. `findGaps()`/`summarise()` are pure; `buildGapsXlsx()` in xlsxIO emits one sheet per month containing ONLY the unfinished days, pre-filled with what exists, in the same month-grid layout `parseMonthGrid` reads — so the file round-trips through /import, which upserts and never deletes. The share card carries an "Unlogged" row for the same reason: the column has to sum to 24. Linked from Settings > Your data and /export; NOT a nav tab.

Built-ins: Life (auto-join everyone incl. via handle_new_user) and Lifts (routes to /lifts, users with lift data auto-joined).
